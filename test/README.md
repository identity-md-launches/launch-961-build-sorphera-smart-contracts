# Sorphera adversarial tests

Run `forge build` and `forge test` with the existing configuration. No added packages, RPC URL, keys, environment mutation, or configuration edits are required.

`SorpheraAdversarial.t.sol` adds atomic rollback for invalid batches and payment errors; empty/oversized maintenance and claims; mixed-owner and duplicate claims; every one of the 5,700 valid combinations with all six permutations and collision checks; malformed/unknown VRF callbacks; active-rule snapshots; paused-sales settlement; an NFT receiver that owns the winning ticket and attempts a second claim during delivery; minimum-price cancellation and sub-ticket late recovery accumulation. The price/refund property runs 1,000 bounded examples, including the supported minimum/maximum through Foundry's bound mapping.

`SorpheraInvariant.t.sol` uses three actors and independent games over bounded random sequences. Inline settings travel with the suite: 256 runs, depth 64, unexpected handler reverts fail the run. Its handler drives sales, blackout failures, acquisitions, allocations, settlements, refunds, vault donations and synchronization, separate VRF callbacks/finalization, up to four rounds per game, late claims, failed/retried NFT transfers, unauthorized withdrawals, pauses, purchaser epoch rewards, builder allowance claims, helper failures, and queued-token delivery. Predetermined mock words deliberately reach matching and nonmatching tickets. The existing sampler fuzz tests cover arbitrary words.

The properties compare independently tracked incoming/outgoing ETH with held assets, reconcile liabilities against reserved fees/cash/unpaid ticket entitlements, check each game's conservation independently, account for purchaser and builder tokens separately including helper escrow, and check pending-request counts, actual NFT custody, and persistent terminal states/random words. Ghost variables update only after successful calls. A deterministic handler lifecycle ensures claims and retry paths are exercised without depending on random reachability.

All FWA, NFT, rewards, Permit2, helper, and lottery-coordinator behavior in these tests is mocked using the existing local models. The mock quote and reward conversion rate are harness inputs, not live protocol constants or revenue promises. ERC721 ownership checks assume compliant collections. These tests do not establish deployed FWA compatibility, authentic Chainlink proofs, live settlement timing, market liquidity, or subscription funding. The existing `integration/Sepolia.t.sol` and `docs/DEPENDENCIES.md` describe the separate real-dependency checks and published Sepolia compatibility blocker; no new live fork run is claimed here.

A reproduced custody/deadline defect is reported in the root `.imd-findings.json`, with its self-contained failing Foundry source embedded as `proof`. It is intentionally absent from the passing suite. To reproduce, save that source as `test/scratch/SorpheraCustodyDeadlineProof.t.sol` and run `forge test --match-path test/scratch/SorpheraCustodyDeadlineProof.t.sol`. Scratch files are excluded from submission. No production implementation or protected configuration was changed.
